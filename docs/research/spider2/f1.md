# F1 (Spider 2.0-lite): reverse-engineered event log

Source: `data/spider2/f1.sqlite` (72 MB, sha256 `35ad3b82…34ce23`), opened read-only. Scripts are in `scripts/f1/`:
- `rq.py` copies the file into an in-memory SQLite and runs the named blocks of a `.sql` file. The source file is never written.
- `q*.sql` are the named-block query files. `p*.py` are Python probes, run with `python3 -I`; `p8` runs under `uv run` because it needs DuckDB.
- Raw outputs are next to them, as `out_<script>.txt`.
- Gold SQL and CSVs fetched from the Spider2 repository are in `scripts/f1/gold/`.

A reference such as `[q3:team_driver_ranks]` means file `q3_derived.sql`, block `-- name: team_driver_ranks`. `[p4]` means `p4_drives_probe.py` and its output.

## 0. What this catalog is

- **Dataset.** It is the **Ergast Developer API** Formula 1 database: every World Championship race from 1950-05-13 to 2024-07-07 [q1:snapshot]. Spider2, or an upstream author, added 15 tables to it. The evidence:
  - The 14 base tables are exactly Ergast's schema (`circuits`, `constructor_results`, `constructor_standings`, `constructors`, `driver_standings`, `drivers`, `lap_times`, `pit_stops`, `qualifying`, `races`, `results`, `seasons`, `status`, `sprint_results`). The columns are renamed from camelCase to snake_case (`raceId` → `race_id`), and Ergast's MySQL types survive in the DDL: `INT(11)`, `VARCHAR(255)`, `DEFAULT '0'`.
  - Ergast's coverage boundaries are all present: qualifying from 1994, lap times from 1996, pit stops from 2011, sprints from 2021, and the `fp*/quali/sprint` session columns from 2021 [q1:coverage_by_table, q4:race_time_formats].
  - The Ergast ids are kept. `race_id` is not chronological: 61 of 1,114 consecutive id pairs go back in time [q1:race_id_vs_date]. Shared 1950s drives were appended late, with result ids 20097+ for 1950s races [p4].
- **The snapshot.** The 2024 calendar is complete (24 rounds), but results end at round 12 (British GP, 2024-07-07). 12 races have no results [q1:snapshot]. Lap times end one race earlier (2024-06-30): race 1132 has results and 45 pit stops but no laps [q6:pit_stops_without_laps_race]. Ergast was deprecated at the end of 2024, so this is a mid-2024 dump.
- **Spider additions (15 tables).**
  - Four hand tables: `short_grand_prix_names` 40, `short_constructor_names` 44, `liveries` 64 (hex colours; 3 rows say `benneton`, a typo that matches no constructor) and `tdr_overrides` 48.
  - Two generated columns, declared `VIRTUAL`: `drivers.full_name`, and `seconds` in `lap_times` and `pit_stops`.
  - Eleven derived tables: `circuits_ext`, `constructors_ext`, `drivers_ext`, `races_ext`, `driver_standings_ext`, `lap_times_ext`, `lap_time_stats`, `team_driver_ranks`, `drives`, `retirements`, `lap_positions`.

  They look like the helper layer of an overtakes analysis: the external-knowledge file `f1_overtake.md` is cited by local336 and local344. I found no public source with these table names (web search, unverified).
- **Row counts** [q1:row_counts]. Total 1,349,640.

  | Group | Rows |
  |---|---|
  | Base, larger | lap_times 575,029; driver_standings 34,595; results 26,519; constructor_standings 13,271; constructor_results 12,505; pit_stops 10,990; qualifying 10,254 |
  | Base, smaller | races 1,125; drivers 859; sprint_results 300; constructors 212; status 139; circuits 77; seasons 75 |
  | Hand tables | liveries 64; tdr_overrides 48; short_constructor_names 44; short_grand_prix_names 40 |
  | Derived | lap_positions 613,112; lap_times_ext 575,029; driver_standings_ext 35,012; retirements 11,568; lap_time_stats 10,789; drives 3,784; team_driver_ranks 3,530; races_ext 1,125; drivers_ext 859; constructors_ext 212; circuits_ext 77 |
- **Licence.** Unstated in the file. Ergast published its data for non-commercial use; the licence most often cited for it is CC BY-NC-SA, which I have **not verified**. The hand tables' origin is unknown.
- **Nature.** **Real** public sports results. The data is not anonymised and not generated. The 15 extra tables are rule outputs plus four small hand tables.

## 2. Event catalogue

**Times.**
- Races have a `date` for all 1,125. They have a UTC start `time` only for 394 (2005+); 731 are NULL [q4:race_time_formats].

- Qualifying has a date only for 2021+ (1,558 rows); 8,696 rows have none [q6:qualifying_time_source]. Sprints have a time for 240 of 300 rows.

The lap-0 rows of lap_positions work as follows:
- position = grid, or the race's entry count when grid = 0.
- The type is chosen in this order:
  - no qualifying row: `No Qualification`;
  - grid 0: `Pit Lane Start`;
  - grid > qualifying position: `Grid Drop`;
  - grid < qualifying position: `Grid Increase`;
  - otherwise: `Qualifying`.
- DISTINCT collapses 4 shared-drive duplicates.

Two tables are not exact by rule:
- **`lap_time_stats`** has one row per lap_times (race, driver), 10,789 [p2, p8].
  - `avg_milliseconds` = avg(ms): bitwise exact in SQLite, Python and DuckDB.
  - `avg_seconds` = the **naive left-to-right sum, in lap order**, of ms/1000, divided by n. That is exact in 10,789 rows. SQLite's `avg(seconds)` matches only 3,814, because SQLite ≥ 3.43 uses compensated summation. In DuckDB, `list_reduce(list(ms/1000.0 ORDER BY lap), +)/n` is exact in 10,789.
  - `stdev_*` = the **population** stdev as Python's `statistics.pstdev` (exact rational arithmetic, correctly rounded): exact 10,789/10,789. The sample stdev matches only the 114 single-lap rows.
  - DuckDB's best is `sqrt((n·Σx² − (Σx)²)::double / n²)`, exact in 9,522; `stddev_pop` is exact in 2,199. **Every candidate is within 1e-9 in all 10,789 rows.** The comparator applies 1e-9 to float64 columns (`apps/dataset/src/dataset/tables.py`, `REL_TOL`), so the table passes. A bitwise rebuild needs a pstdev UDF.
- **`drives`** has 3,784 rows: one per run of consecutive rounds with one constructor, per (year, driver). It has flags for the season's first and final drive, plus `drive_id = -1, constructor_id = -1` gap rows (163) spanning missed rounds between two drives.
  - This rule rebuilds **3,754 of 3,784** rows. The other 30 lie in 17 driver-seasons [p4]; 16 of those have a round driven for two constructors (1950s shared cars).
  - In those seasons the source does things no clean rule gives: both cars get `drive_id` 1 with first = final = 1; rounds 6–8 vanish in 1961/475; a gap row is missing in 1961/486.
  - Proposal: build by rule and replace those 17 driver-seasons (39 rows) from a `drive_overrides` entity. The alternative is to carry `drives` verbatim.

### 3.2 Base tables measured against results (`p6`, `p7`)

- **driver_standings:**
  - points = the season's cumulative results + sprint points in 34,469 of 34,595 rows. The misses are 126 rows in 1950–1990, the dropped-scores era.
  - wins = cumulative race wins (sprint wins excluded) in **34,595/34,595**.
  - position = rank by (points, countback) in only 26,564; by points alone, 15,087.
- **constructor_standings:** points = the cumulative sum of cars in 12,335 of 13,271. With the "best car only, 1958–1978" rule, 13,077. The rest are:
  - 1958–1977 residue;
  - McLaren 2007, excluded (`E` ×17 [q4:standings_position_text]);
  - 2018 Force India and 2020 Racing Point.
- **constructor_results:** points = the sum of cars in 12,196 of 12,505; best car 1958–1978 gives 12,477. 7 rows have no results.

**Verdict.** These are near-derived but carry official adjustments. Carry them as reported events E7–E9 and do not derive them.

### 3.3 Text formats [q4]

- **`lap_times.time` is a pure function of ms** (575,029/575,029): `m:ss.sss`, or `h:mm:ss.sss` for the 43 red-flag laps over 1 h. Carry only ms and format in `build.sql`.
- **`pit_stops.duration` is a function of ms** (10,990/10,990): `s.sss` below 60 s and `m:ss.sss` above (500 stops, up to 51 min under red flags). `pit_stops.time` is local `HH:MM:SS` text, carried verbatim.
- **`results.time` is *not* a function of ms.** Only 753 of 1,122 winner times fit `h:mm:ss.sss`; old gaps use 1–2 decimals (`+5.7`, `+8:22.19`). Decimals by era: 1 decimal for 857 rows (1950–2007) and 2 for 723 [q4:winner_time_decimals_by_era]. Carry it as text. `time` and `milliseconds` are NULL together (0 mismatches).
- **`position_text`** is `R` 8,876, `F` 1,368, `W` 334, `N` 190, `D` 149, `E` 9 (position NULL), else the number. In 13 rows position ≠ position_order (all in 1983 race 452, where position runs one ahead of position_order). 2 rows (2005 race 71) have a numeric text with a NULL position [q4:position_ne_order].
- **`rank = 0`** in 250 rows with no fastest lap (2011–2024). NULL appears elsewhere. Keep the distinction.
- **`fastest_lap_speed`** is text with trailing zeros (836 end in `0`). Carry it verbatim.
- **Qualifying:**
  - `''` ≠ NULL: q2 has 13 `''` and q3 has 27, all in 2023–24; NULLs are q1 154, q2 4,572, q3 6,713.
  - One q1 is `16:42.640`.
  - Carry all three as opt text.
- **Points (REAL)** take 39 values, including 1.33, 8.14 and 3.14 (shared drives). They are carried as f64 and compare by value.
- **Dates** are all ISO `YYYY-MM-DD`. Race `time` and session times are `HH:MM:SS` or NULL. There is no `'\N'` and no `''` outside qualifying [p1].
- **Generated columns.**
  - `PRAGMA table_info` hides `drivers.full_name`, `lap_times.seconds` and `pit_stops.seconds`. `apps/dataset/.../tables.py` reads `table_info`, so results will lack them.
  - Spider queries can use `full_name`. So the rebuilt SQLite must declare the same VIRTUAL columns. Otherwise the saved queries on the rebuilt file will fail (§7).
- **Results types under the new contract** (stored classes):
  - `drivers_ext.dob` (`NUM`) and `races_ext.date`/`time` (`NUM`) hold only text, so they are string.
  - The untyped ext columns hold one class each, so they are int64, float64 or string.
  - No column is mixed.

## 4. Measured quirks

- **Shared drives:**
  - 91 duplicate (race, driver) results [q1];
  - points such as 1.33 and 8.14;
  - 4 duplicate lap-0 rows;
  - the 30 `drives` anomalies.
- **Standings gaps:** 469 (race, driver) results have no standings row. `_ext` fills 417 [q3:driver_standings_gaps].
- **Truncation at N:**
  - race 1132 has results and pit stops but no laps;
  - 12 future races are in races and races_ext, with `number_of_races` counting them;
  - 3 future sprint weekends have `sprint_date` but `has_sprint = 0`.
- **Penalty fingerprints:** McLaren 2007 `E` and constructor_results `status = 'D'` (17 rows); Schumacher 1997 `D` in driver_standings.
- **Pit and lap anomalies:**
  - pit duration p99 = 31 min (red-flag stops);
  - lap ratio p100 = 35.8 × the driver's mean [q5:pit_duration_quantiles, q5:lap_ratio_to_driver_median];
  - 10 exact ties of (race, running ms) between drivers [q6:lap_events_same_time].
- **Ids are not in time order** (61 race_id inversions). Rounds are strictly date-ordered within each year (0 violations) [q5:round_vs_date].
- **Hand-table dirt:** `benneton` (3 liveries rows) and 1 overlapping livery span.

**Ingest.**
- `race_id` is a plain `i64` in every event, not a ref, because races are an event (E1).
- Owners: E1 is owned by `circuit_id`; E2–E6 and E8 by `driver_id`; E7 and E9 by `constructor_id`.
- `ord` and ORDER BY per block:

  | Event | ord | ORDER BY |
  |---|---|---|
  | E1 | race_id | year, round |
  | E2 | race_id | race_id, position |
  | E4 | running_milliseconds | race_id, running_ms, driver_id |
  | E5 | race_id | race_id, driver_id, stop |
  | E6 | race_id | race_id, position_order, result_id |
  | E7 | race_id | race_id, constructor_results_id |
  | E8 | race_id | race_id, driver_standings_id |
  | E9 | race_id | race_id, constructor_standings_id |

- E6–E9 share one timestamp and sort by block position, so results come before standings.
- E4 times use `iso_time(date || ' ' || coalesce(time, '12:00:00'))` + running ms.
- Volume is about 685k events. 84% are laps, so a sample profile could drop laps before 2011.

**build.sql** (DuckDB):
- **Base tables** come from their events or entities 1:1.
  - `lap_times.time` and `pit_stops.duration` are formatted from ms with the two `printf` rules in §3.3.
  - `drivers.full_name` and the `seconds` columns are declared VIRTUAL in the rebuilt DDL.
- **Derived tables** use the SQL in `q3_derived.sql`, ported to DuckDB. The ports need care in three places:
  - `driver_standings_ext`: the surname ordering must use binary collation (`COLLATE binary`; DuckDB's default is binary).
  - `lap_time_stats`: a list_reduce in lap order for avg_seconds, and a pstdev UDF (or the integer formula, which is within 1e-9).
  - `drives`: the run-length rule plus `drive_overrides`.

**Stage-2 owners.**
- Race weekend is the unit: one shard per race. It emits qualifying, laps (positions from cumulative times), pits, retirements (lap = laps + 1), then classification and standings.
- Drivers and constructors are the entity owners.

## 7. Open questions and risks

- **Generated columns vs `table_info`.** The results writer drops `full_name` and `seconds` (hidden). Either the dataset adds them back as VIRTUAL columns in the rebuilt SQLite, or questions using `drivers.full_name` must be rewritten. Decide before building.
- **`drives` tie rule.** 30 rows in 17 shared-drive seasons are not reproduced by any clean rule I tried [p4]. A hypothesis, **untested**: `drives` was computed on an older Ergast snapshot, before the late shared-drive result ids 20097+. Until that is settled, use `drive_overrides` (39 rows) or carry the table verbatim. local354 and local355 depend on it.
- **`lap_time_stats` bitwise.** It passes under the 1e-9 float tolerance, but a pure-SQL DuckDB rebuild is not bitwise. If the contract ever drops tolerance, a Python UDF is needed.
- **Standings as reported events.** This is exact, but stage 2 must generate standings by the points rules of each era, and §3.2 shows those rules have exceptions (penalties, dropped scores). The residues are listed in `out_p7_standings_rules.txt`.
- **Invented times.** E1 (Jan 1), E2 before 2021 (race − 1 day 12:00), E4 before 2005 (12:00 start), E5 (the in-lap time) and E6–E9 (the day after the race) are rules. Stage 2 must not fit them. Pit-stop local clocks show the true intra-race timing.
- **Licence.** Ergast's terms (non-commercial, attribution) are unverified, and the hand tables' authorship is unknown. Fitting statistics is fine; redistribution needs a check.
- **Origin of the 15 extra tables** is unverified: there are no public hits for `tdr_overrides` or `team_driver_ranks`.
- **Gold coverage.** 5 of 9 questions (overtakes, 1950s drives) were not reproduced. They need `f1_overtake.md`, which is not in this repository's metadata.

**Summary**
- Round trip: **yes, with caveats**. Every table is rebuildable. 10 derived tables are exact by SQL. `lap_time_stats` is within 1e-9 (bitwise needs an exact-pstdev UDF). `drives` needs 39 override rows.
- Dataset name: **`f1`**.
- **9 event types** (684,588 events) and **10 entities** (1,597 rows). 11 tables are derived and produce no events.
- Event shape: **partly imposed**. Laps, pits and results have natural race-relative times. Scheduling, qualifying (pre-2021), classification and standings times are rules, and the standings are pre-aggregated reported facts.
- Hardest blocker: **`drives`**, whose shared-drive tie behaviour (30 rows) matches no rule. Next is the generated columns that `table_info` hides.
