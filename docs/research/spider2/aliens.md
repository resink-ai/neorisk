# Aliens (Spider 2.0-lite, `city_legislation`): reverse-engineered event log

Source: `data/spider2/city_legislation.sqlite` (44 MB), opened read-only. The file holds four unrelated catalogs. This report covers four tables: `aliens`, `aliens_details`, `aliens_location` and `alien_data`. The others are covered in `legislators.md`, `jobpostings.md` and `cities.md`.

`scripts/aliens/rq.py` copies the file into an in-memory SQLite and runs named blocks (`setup*` blocks index the in-memory copy); the file itself is never written. Every number below comes from one of these scripts:
- a named query in `scripts/aliens/q*.sql`;
- `profile.py` (per-column storage classes, NULL / `''` / `'\N'` counts);
- `f1_generator.py` (generator fingerprints and uniformity).

The raw outputs are in `scripts/aliens/out_*.txt`. A reference such as `[q1:gender_map]` means file `q1_derived.sql`, block `-- name: gender_map`. The gold CSV is in `scripts/aliens/gold/`.

## 0. What this catalog is

- **Dataset.** 50,000 fictional "aliens living in the US", each with a name, email, gender, alien type (Flatwoods, Nordic, Reptile, Green, Grey), birth year, favourite food (an animal), feeding frequency, an aggression flag, an occupation and a US city. It is split into three 1:1 tables, plus `alien_data`, a cleaned and denormalised copy.
- **It is generated by [Mockaroo](https://mockaroo.com).** The evidence:
  - every email is `lower(first initial + last name, letters only) + base36(id − 1) + '@' + domain`: 50,000 of 50,000. That is Mockaroo's "Email Address" field keyed on the row number [f1_generator];
  - there are exactly **500 distinct email domains** (nature.com, vinaora.com, usatoday.com, joomla.org …), which is Mockaroo's domain list [f1_generator];
  - its other built-in field types show up: favourite food is "Animal Common Name" (1,498 values such as `Stork, european`); occupation is "Job Title" (195 values such as `VP Quality Control`); gender has Mockaroo's 8 values, with Female 22,730 and Male 22,323 and the other six about 800 each [f1_generator];
  - the categorical columns are uniform and independent. Type is 9,931–10,124 per value; feeding frequency 6,077–6,490 for each of 8 values; aggressive 25,053 / 24,947. The aggressive share is 0.489–0.510 in every type and frequency; mean birth year is 1821–1823 in every type [f1_generator];
  - birth_year is uniform on 1672..1972: 301 years, 132–199 rows each [f1_generator]. City and state are drawn population-weighted: Texas 5,413, California 5,410 … with 30 at the low end [f1_generator].
- **Publisher unknown.** No upstream copy was located. The tutorial that built `alien_data` is unidentified (§7).
- **Row counts** [profile]: 50,000 in each of the four tables.
- **Licence.** Unstated. Mockaroo output carries no licence of its own.
- **Nature.** **Generated**, fictional data, with no time dimension at all.

## 1. Inventory, keys, joins

No PK or FK is declared. All keys below are verified unique, and every table's rowid equals its id (50,000 of 50,000 each) [q1:keys, q1:rowid_is_id].

| Table | Rows | Key | Kind |
|---|---:|---|---|
| aliens | 50,000 | id 1..50,000 | entity: identity |
| aliens_details | 50,000 | detail_id 1..50,000 | entity: the same alien (detail_id = id) |
| aliens_location | 50,000 | loc_id 1..50,000 | entity: the same alien (loc_id = id) |
| alien_data | 50,000 | id | **derived**: lowercased join of the three (§3.1) |

- id = detail_id = loc_id joins all four tables 1:1:1:1, with 50,000 rows and 0 orphans [q1:keys]. The three base tables are one entity split vertically; there is no separate "detail" or "location" thing, since each row is used by exactly one alien.
- `current_location` is a city name, not a key: 29 of 461 names occur in more than one state (Albany NY/GA, Arlington VA/TX …) [f1_generator]. `country` is the single value 'United States' [profile].

## 2. Event catalogue

There are **no business events.** No table has a time column, and nothing happens to an alien.

Entities (1, 50,000 rows):
- **aliens**: ext_id = id. Its attributes are the union of `aliens`, `aliens_details` and `aliens_location`: first_name, last_name, email, gender, type, birth_year, favorite_food, feeding_frequency, aggressive, current_location, state, country, occupation.
- **created_at by rule: 2024-01-01T00:00:00Z**, one timestamp for all 50,000. `alien_data.age` is exactly `2024 − birth_year` in all 50,000 rows [q1:age_rule], so 2024 is the data's own "as of" year. That is the only date the catalog implies.
- Location and occupation are **snapshot columns** (a "current" location, and an occupation that can change). With a single time stamp, creation and snapshot coincide. Classing them as snapshot changes only which event carries them: one `aliens_snapshot` at N = 2024-01-01.

What is **not** an entity or an event, and why:
- **`aliens_details` and `aliens_location` are not separate entities.** They are the same 50,000 rows keyed by the same id; giving them their own keys would invent relations the data does not have.
- **`birth_year` is not a birth event.** It is a generated attribute in 1672–1972. Stamping 50,000 `alien_born` events in the 17th–20th centuries would be pure invention, with a natural-looking time that is not natural.
- **`alien_data` produces no events.** It is derived (§3.1).

## 3. Rebuild rules and blockers to an exact round trip

1. **`alien_data` is an exact function of the three base tables**: 0 rows differ, EXCEPT in both directions, using only literal maps [q1:full_rebuild_literal_maps]. The rules:
   - every text column is `lower()` of its source, column for column. 13 of 13 match in all 50,000 rows, except first_name [q1:per_column_lower_match];
   - **`first_name` = NULL where the source is the name `'Nan'`** (4 aliens: 17710, 26428, 37143, 37773) [q1:null_first_names]. This is pandas reading the string "Nan" as NaN, a loader fingerprint. No other 'NaN'-like name exists in either name column [q1:nan_names_elsewhere];
   - **gender** maps Female → female and Male → male, and the six others (Agender, Bigender, Genderfluid, Genderqueer, Non-binary, Polygender) → `non-binary` [q1:gender_map];
   - **age** = 2024 − birth_year [q1:age_rule];
   - **us_region** is a function of state (51 of 51 states map to one region) [q1:region_is_function_of_state]. It is the 8 **BEA regions**: far west, great lakes, mideast, new england, plains, rocky mountain, southeast and southwest. District of Columbia is in mideast [q1:region_map]. `build.sql` carries this as a 51-row VALUES list;
   - the columns are reordered: id, names, email, gender, type, birth_year, age, food, frequency, aggressive, occupation, location, state, us_region, country.
2. **Lowercasing merges spellings.** 31,037 distinct last names become 31,034 (such as `von Nassau` and `Von Nassau`) [q1:case_collisions]. That is harmless, because the derivation runs forward from the base tables.
3. **Types.** All columns are TEXT or INTEGER (`aggressive` is 0/1, `birth_year`, `age`, ids). No REAL, no `''`, no `'\N'`. The only NULLs are alien_data's 4 first names [profile].
4. **No times to format.** `created_at` is a rule (§2), and no source column holds a date.

**Verdict:** exact. The three base tables are carried verbatim on one entity, and `alien_data` is built by the SQL above.

## 4. Measured quirks

- **The `'Nan'` → NULL artefact** in `alien_data.first_name` (4 rows) [q1:null_first_names].
- **Generator fingerprints:** the base36 email suffix equals id − 1 in every row, and there are 500 domains (§0) [f1_generator].
- **Implausible but intended:** ages 52–352 [profile], and aliens born in 1672 working as `Web Developer IV`.
- **No correlations:** aggression does not depend on type or feeding frequency, and birth year does not depend on type (§0). Any "insight" a question finds in this catalog is sampling noise. local202's margins are about 1% (§0.1).
- **Population-weighted geography:** Washington (DC) is the top city with 1,661, equal to the state count of District of Columbia (1,661). Houston has 1,015 [f1_generator].

## 5. Distributions to fit (stage 2)

| Quantity | Value |
|---|---|
| arrivals | none; there is no time dimension |
| type | uniform over 5 (9,931–10,124) [f1_generator] |
| gender | Female 45.5%, Male 44.6%, six others about 1.6–1.7% each [f1_generator] |
| feeding_frequency | uniform over 8 (6,077–6,490) |
| aggressive | Bernoulli(0.5): 24,947 of 50,000 |
| birth_year | uniform integer on 1672..1972 |
| state | population-weighted over 51 (Texas 5,413 … minimum 30) |
| occupation | 195 titles, 84–474 each; favourite food 1,498 animals, 16–54 each |
| independence | all columns independent (aggressive share 0.489–0.510 across every type and frequency) |

A stage-2 generator is a column-wise independent sampler; there is nothing temporal to fit.

```python
    # snapshot columns (aliens_snapshot at N = 2024-01-01):
    "current_location": text(), "state": text(), "country": text(), "occupation": text()})
```

Ingest: one block, `SELECT … FROM aliens JOIN aliens_details ON detail_id = id JOIN aliens_location ON loc_id = id ORDER BY id`, with created_at = `'2024-01-01T00:00:00Z'`. There are no event blocks.

`build.sql`:
- `aliens` = (id, first_name, last_name, email, gender, type, birth_year) from the entity;
- `aliens_details` = (id AS detail_id, favorite_food, feeding_frequency, aggressive);
- `aliens_location` = (id AS loc_id, current_location, state, country, occupation);
- `alien_data` = the §3.1 SQL over those three: lower(), `'Nan'` → NULL, the gender CASE, 2024 − birth_year and the BEA region VALUES.

## 7. Open questions and risks

- **A catalog with no events.** The log would be 50,000 `aliens_created` events (plus snapshots) at one instant. It round-trips, but it exercises nothing about stream processing. Consider whether it belongs in the benchmark at all, or only as a "static reference" control case.
- **Publisher unknown.** The Mockaroo origin is proven by fingerprint, but the tutorial that produced `alien_data` (with its pandas `'Nan'` bug and BEA regions) is not identified, so the licence is unknown. The data is fictional, so the risk is low.
- **The 2024 rule.** created_at = 2024-01-01 rests on the age formula. Any other constant also round-trips; pick one project-wide for timeless catalogs.

## Summary

- Exact round trip: **yes**. The base tables are carried verbatim, and `alien_data` rebuilds with 0 differing rows.
- Proposed dataset name: **`aliens`**.
- Event types: **0** business events (only `aliens_created` and `aliens_snapshot`); **1** entity (aliens), with `alien_data` derived.
- Event shape: **mostly imposed**. It is generated, timeless data, and every time is the rule 2024-01-01.
- Hardest blocker: none technical. The real issue is that the catalog has no time dimension, so a log of it carries no event information. The only subtle rule is pandas' `'Nan'` → NULL.
