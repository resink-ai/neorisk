# oraclesh

## What this is

Oracle Sales History: unit sales by channel and promotion, and periodic unit cost and price quotes.

Version `v1`, kind `spider2`. The input is one ordered event log of 1,063,399 events; the output is the 10 source tables, rebuilt exactly, and the answers to 6 saved Spider 2.0 questions.

## Raw data

`complex_oracle.sqlite`, 10 tables. A generated sample schema; MIT licence (Oracle).

Dates only, read as midnight UTC. currency is a rule; the 3 SQLite views are not data.

The reverse-engineering research, with the queries behind every number, is in [`docs/research/spider2/oraclesh.md`](../../docs/research/spider2/oraclesh.md).

## How the log was made

Each sale is a `unit_sold` event owned by the customer, and each cost quote a `price_quoted` event owned by the product. Countries, channels, promotions, customers, the calendar (`times`), products (51 placeholders for sold products with no product row) and demographics are entities. The currency table is generated by its rule.

`uv run dataset build oraclesh` runs `specs/ingest.sql` on the read-only source to make a simkit dataset (an internal stage), then writes it as one log. Entity rows become `<entity>_created` events at their creation time; business events keep their columns. The log is in `seq` order: event time, then entities before events at the same instant. Each row's `payload` is a JSON object whose fields are listed in `schema/events.json`.

## Expected output

`results/` holds every source table, as the source stores it. Each column's type follows the values it holds: text, int64 or float64. A mixed column holds text and numbers together, so it is stored as SQLite's own text rendering and declared in `dataset.toml`.

| Table | Rows | Columns | Mixed columns |
|---|---:|---:|---|
| `countries` | 35 | 9 | none |
| `customers` | 55,500 | 23 | none |
| `promotions` | 503 | 11 | none |
| `products` | 24 | 22 | none |
| `times` | 1,826 | 38 | none |
| `channels` | 5 | 6 | none |
| `sales` | 918,843 | 7 | none |
| `costs` | 82,112 | 6 | none |
| `supplementary_demographics` | 4,500 | 14 | none |
| `currency` | 1,260 | 4 | none |

`expected/queries/` holds the answers of the saved questions (`local050`, `local060`, `local061`, `local062`, `local063`, `local067`), computed on the source. `dataset verify` runs `specs/build.sql` over the log, loads the tables into SQLite with the source's DDL, and compares them and the answers exactly: rows as multisets, numbers by value, text byte for byte.

## Regenerate

```bash
uv run refdata fetch                 # once: the Spider 2.0 SQLite files → data/spider2/
uv run dataset build oraclesh             # → $NEORISK_DATA_ROOT/oraclesh/v1/ (default data/datasets/)
uv run dataset verify oraclesh            # exit 0 = every table and answer matches
```

## Extend

- **More rows:** not possible for a fixed source. Stage 2 will generate logs from `specs/pack.py`.
- **A new event type:** declare it in `specs/pack.py`, add its `-- event: <name> owner=<col>` block to `specs/ingest.sql`, and use it in `specs/build.sql`.
- **A new attribute:** add the column to the pack table and to its ingest block. It then appears in the payload and in `schema/events.json`.
- **A new results table:** add it to `specs/source.toml` and a `-- table: <name>` block to `specs/build.sql`.
- **A new saved question:** add `specs/queries/<id>.sql` (SQLite dialect, source table names).
- **A new engine port:** write `engines/<engine>/` from `specs/build.sql`. It must read only the log and match `results/` exactly.

Any change to `specs/`, `dataset.toml` or the source changes the build. Once a version is recorded in `v1.lock.json`, changed output needs a new version (`v2`).
